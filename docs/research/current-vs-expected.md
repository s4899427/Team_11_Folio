# What We Have vs. What Users Expect
Built from all 13 interviews (6 Round 1 + 7 Round 2, including Dylan's and his interviewee's).

| User expectation (from interviews) | Do we have it? | What we have | Gap / next step |
|---|---|---|---|
| No algorithm, human-curated discovery | ✅ Yes | Today's Thread, picked by a verified curator, no recommendation engine anywhere | None — this is the core design already |
| Clear line between "inspiration" and "killing time" | ✅ Yes | Bounded Thread (locks at midnight), no infinite scroll, Archive requires deliberate "Load more" | None — directly matches the 6/6 pattern in interviews |
| Discovery through trusted people/trails, not open categories | ⚠️ Partial | Onboarding is category-based (6 areas); artist entries exist but aren't strongly cross-linked | Add "related entries" links (artist → similar artists, piece → related pieces) |
| Curator has to feel credible, not random/promotional | ❌ Not solved | Single hardcoded curator per Thread; no rotation model, no credibility signal | **Most urgent open item** — needs a real answer before Week 9 |
| Retention beyond week one (not "one more app I ignore") | ❌ Not addressed | No mechanism to keep Threads feeling fresh/worth returning to | Needs discussion — possibly tied to curator rotation quality |
| Coordinating outfit/vibe with friends for an occasion | ✅ Yes, scoped correctly | Tonight's Theme — optional, occasion-based, not a daily nag | Matches real behaviour precisely; no major change needed |
| Wanting to build on/improve others' work, not just react | ✅ Yes | Remix post type exists | None |
| Preferring private drafts over public remix sometimes | ✅ Yes | Drafts feature (separate from published posts) | None — directly validated by multiple participants |
| Attribution matters less than assumed for genuine reinterpretation | ⚠️ Partial | Posts aren't currently attributed/linked back to an "original" | Consider: light-touch lineage (optional "inspired by" tag) rather than mandatory heavy attribution |
| Low-pressure, optional commenting (not obligatory) | ✅ Yes | Comments exist but aren't prompted/forced; posting itself is the main action | None — matches "sometimes I deliberately don't comment out of respect" finding |
| Wanting cultural/historical context behind what you wear/consume | ✅ Yes | Entry detail pages show background/context, "multiple perspectives" model | None |
| Music as mood-regulation, not just discovery | ⚠️ Partial | Music entries exist with preview clips, but no explicit mood framing | Minor — could tag entries by mood as a lightweight addition, not essential |
| Wanting genuinely different content each day (not repetitive) | ⚠️ Depends entirely on curator quality | Structurally possible (any domain, any combination) — but only as good as who's curating | Tied to the same curator rotation problem above |
| One place instead of switching between Spotify/Pinterest/Instagram/Letterboxd | ✅ Yes, directly | This is the core pitch — one app across music/art/fashion/film/food/design | None — strongly validated, several participants described exactly this fragmentation pain |
| Wanting to see combinations they wouldn't have put together themselves | ✅ Yes | Generalised Thread model (any domain, any number of elements) | None — directly validated by Participant E's quote |

## The one thing to fix before anything else
Nine of fourteen rows are solid or well-scoped. The pattern in what's *not* solved is consistent: **everything traces back to curator credibility and rotation.** That single unresolved decision is blocking retention, freshness, and trust — three separate rows in this table. Solve that one thing and most of the remaining gaps close with it.
